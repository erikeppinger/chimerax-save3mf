3MF export for 3D printing

Saves the scene as a 3MF file, carrying the colouring with it: as extruder assignments for a multi-filament printer, or as a colour at every vertex for a full-colour printer. See Flavours for which to use.

save

save  filename.3mf  [ models model-spec ]  [ size mm ]  [ scale mm-per-Å ]  [ colors true|false ]  [ maxColors N ]  [ flavor prusa|bambu|fullcolor ]  [ paint true|false ]  [ check true|false ]

The scene is written as displayed: whatever is shown in the graphics window is what gets exported, with hidden atoms, clipped surfaces and masked triangles left out. Instanced geometry such as atom spheres and bond cylinders is expanded into real triangles, and coincident vertices are merged so slicers see a connected mesh.

  • models – which models to export; the default is everything displayed.
  • size – scale so the longest edge of the model measures this many millimetres. This is usually what you want: molecules in Ångstroms are not printable sizes.
  • scale – millimetres per Ångstrom, default 1.0. Ignored if size is given.
  • colors – whether to carry the scene's colours into the file (default true). With false only geometry is written.
  • maxColors – merge down to at most this many colours, for a printer with a limited number of filaments. By default nothing is merged. Has no effect with flavor fullcolor, which has no such limit. See 3mf palette to choose the number.
  • flavor – what kind of printer the file is for; see Flavours below.
  • paint – with a filament flavour, paint extruders onto one mesh (default) or, with false, split the mesh into named parts instead. Painting keeps the mesh whole; splitting leaves open edges between the parts but gives each a name in the slicer's part list.
  • check – whether to report printability problems (default true).

The model is placed with its bounding box starting at the origin and its lowest point at z = 0. Coordinates are never negative, because a slicer reading a 3MF without its own placement data takes them literally and anything at negative x or y is off the build plate.

3mf palette

3mf palette  [ models model-spec ]  [ maxColors N ]  [ size mm ]  [ scale mm-per-Å ]  [ layerHeight mm ]  [ tools N ]

Reports the colour parts an export would produce, without writing anything. With no options it also shows what merging to each part count would cost, as colour swatches with the mean perceptual error (ΔE) in plain words, so the number of parts can be chosen before exporting: 

526 distinct colors across 814254 triangles; 307 layers at 0.20 mm,
about 3h 57m spent changing tools (774 changes on a 5-tool printer)
  merge to 2     ΔE 32.5   strong shift       +1h 28m changing tools
  merge to 4     ΔE 21.7   strong shift       +3h 15m changing tools
  merge to 5     ΔE 16.6   strong shift       +4h 40m changing tools
  merge to 8     ΔE 9.3    clearly different  +5h 44m changing tools
  no merge       ΔE 0.0    526 parts          +3h 57m changing tools

With maxColors N it shows that exact palette instead, with the area share, the number of layers each part appears in, and the tool changes it causes.

Print cost

A multi-material print spends most of its time changing tools rather than extruding, and each change purges filament into a wipe tower. What decides the cost of a colour is therefore not its area but how many layers it appears in, since it forces a tool change on each one.

So a part covering a fraction of a percent of the model can still drive a large share of the print time, and the palette says so: 

Part 5 (1a3n_D SES surface red) is 0.4% of the model but drives about 6% of
the tool changes, because it appears in 52 of 269 layers. Dropping it with
'maxColors 4' would save roughly 52 tool changes.

The estimate is the number of extruders present in each layer, less one, summed over layers, times the measured cost of a tool change. Checked against PrusaSlicer on real exports the change count lands within about 1% and the time within 5%.

The time reported is only what is spent changing tools, not the whole print: extrusion time depends on the print profile, which this bundle knows nothing about. On an Original Prusa XL at 0.20 mm a tool change measured 18.4 seconds (tools/calibrate_time.py re-measures it). An MMU, which rewinds and purges rather than swapping a head, is considerably slower, so treat the figure as a way of comparing choices rather than a quote.

Colours beyond the printer's tool count cost no extra time, because they all print with filament 1 – which is why the ladder stops rising past that point. Tell it what the printer has with tools N (default 5).

Because the layer count depends on how tall the print is, size and scale mean the same here as in save, and layerHeight (default 0.2 mm) should match the print profile you intend to use.

Colours are clustered in CIELAB rather than RGB, weighted by triangle area, so merging follows what the eye calls similar and a large surface is not merged away in favour of a few tiny ligand triangles. Each part keeps a colour that actually appears in the scene rather than a cluster average.

Flavours: which printer is this for?

A multi-filament printer and a full-colour printer need different files, and the two filament slicers store multi-part models in incompatible ways, so no single file works everywhere.

flavorColour written asFor
prusa (default) per-triangle extruder painting, slic3rpe:mmu_segmentation; at most 15 colours PrusaSlicer, multi-filament printers
bambu per-triangle extruder painting, paint_color; at most 15 colours Bambu Studio, OrcaSlicer
fullcolor a colour at every vertex, interpolated across each triangle (Materials-extension colorgroup); no colour limit full-colour printers – inkjet, binder jet, PolyJet – and 3MF viewers

fullcolor is the one to use for continuous colouring such as mlp or colouring by B-factor: it writes the scene's colours unchanged, with no clustering and no extruder assignment. generic is accepted as an older name for it.

Multi-filament printers work the other way round: a filament is a physical thing, so the colours must be reduced to as many as the machine has tools. That is what maxColors and the palette preview are for.

Each colour is written as an extruder already assigned to those triangles, so a multi-tool printer needs no manual assignment at all.

Painting rather than splitting

Colours are painted onto the triangles of a single mesh, which is what a slicer's own multi-material paint tool produces. The mesh keeps its topology, so there is nothing for the slicer to repair.

The alternative is to split the mesh into one part per colour. That also works, and gives each part a readable name in the slicer's part list, but every patch is then edged with open boundaries and the slicer flags a repair warning on each one. Use paint false to choose that layout. It is also used automatically above 15 colours, which is the most a slicer can paint; the log says so when that happens.

Printability report

Unless check false is given, each export reports what a slicer will make of the geometry. Nothing is modified; the report only describes.

ChimeraX geometry is almost never stitched together: a ribbon is a separate surface per helix, strand and coil, atoms are separate spheres, and bond cylinders are open-ended tubes. These abut or overlap rather than sharing vertices, so counting topologically separate surfaces says nothing about what will print. The report is built around what actually decides the outcome.

  • Printed bodies – surfaces that come within roughly an extrusion width fuse in the print, so they count as one body no matter how the mesh is built. Six hundred overlapping atom spheres are one object.
  • Interior cavities – a closed surface wound inside-out bounds a void, not a solid, as in a density map with internal voids. Slicers fill what lies inside an odd number of surfaces, so a cavity stays hollow and costs no filament.
  • Genuinely loose pieces – only geometry touching nothing else, such as a water or ion in space, is reported as printing separately.
  • Open surfaces – stated as a fact with its cause. Bond cylinders have no end caps and clipped surfaces are cut open; slicers close them when slicing.
  • Thin features and extreme sizes – pieces below what a 0.4 mm nozzle can hold, or a model larger than most build plates.

To prepare a structure for printing – struts between disjoint pieces, thickened ribbons, solvent removal – use the NIH 3D print presets bundle. This bundle only measures and reports.

Related

Support Optimizer is a browser-based tool that takes the file saved here and prepares it for the printer: it seals interior cavities so support material cannot be trapped inside them, searches for an orientation with fewer overhangs, and previews the support paths. The cavities reported above are precisely the ones it can seal.
